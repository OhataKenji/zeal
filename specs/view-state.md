# Svelte view state inventory

**Checked** below means the named property of a finite specification, not
verification of Svelte or the browser. **Unverified** means the interaction is
present in the implementation but is not established by that model. Request
controllers have their own models; a proof about stale IPC replies does not
prove that the right row is highlighted or that focus returned to a dialog.

## Checked interaction boundaries

- [`ViewSurface`](ViewSurface.tla) follows [`AppView`](../src/AppView.svelte)
  (`surface`, `opening`, `onWindowKeydown`, `onPaletteSelect`) and
  [`CommandPalette`](../src/lib/CommandPalette.svelte) (`choose`, `onclose`).
  At settled renders a workspace and a single explicit owner are sufficient:
  none, palette, run or workspace prompt. With no workspace the initial
  prompt needs **no** explicit owner (the core-loading screen is omitted).
  Losing the workspace drops a run/palette but preserves an explicit prompt.
  A dirty bit distinguishes preserving a form from mounting a fresh one;
  an explicit path pick represents a different seed. `opening` can also be
  set by a registered switch independently of the visible form.
- `KeyDisposition` distinguishes _preventing the browser default_ from
  _accepting a shortcut_. Ctrl/Meta+O is consumed even when it must leave
  the initial, already-edited or busy prompt alone. Shift+Ctrl/Meta+R is
  consumed with a workspace even if a modal or an ineligible package blocks
  the run form. K toggles only with an eligible owner, without shift, alt or
  repeat. Composing and non-command keystrokes are ignored. Focus is a request
  on palette open, not a claim about `document.activeElement`. `PaletteDispatch`
  distinguishes an accepted choice from repeated/composing Enter or no active
  item: only an accepted choice closes before dispatch. `GuardedClose` checks
  kind at delivery; a queued palette close after native reopen cannot clear it.
  The `dialog.open` observation is an input. Neither a DOM queue nor per-instance
  identity for two successive run dialogs is modeled.
- [`TimelineInteraction`](TimelineInteraction.tla) follows
  [`ProfileView`](../src/lib/ProfileView.svelte) (`pointerDown`, `pointerMove`,
  `pointerUp`, `cancelDrag`, `moveEvent`). Two pointer IDs compete for one saved
  drag. Only a primary-button down in the plot requests capture; another such
  down can replace the drag. A matching move exceeding the threshold latches
  pan until drag ends; a matching up selects a hit only before that latch,
  clears the drag, and requests release only if capture still exists. A foreign
  move/up cannot pan/select/release on its behalf. **Cancel/lost capture is
  different:** the handler unconditionally clears the saved drag; there is no
  per-ID cancel guard. `CaptureOnPlot`, `PanOnlyAfterDrag` and `ReleaseOrIgnore`
  check handler effects, not successful delivery by the browser.
- Unmodified canvas arrows (no Ctrl/Meta/Alt) clamp the event index in the
  selected lane, expand a collapsed lane in the implementation, then await
  `tick()`. `KeyboardSelection` checks the index; `OwnedReveal` checks the
  later scroll/pan belongs to the **current `(tid,index)`**, including after
  Escape, another arrow or a pointer selection. Identity is by value: A→B→A
  need not reject an A reveal. Two lanes with two indices exercise same-index
  collisions; at most two distinct pending destinations may resume in either
  order. Identical destinations are coalesced. Availability of the viewport,
  geometry and need for movement are one input. No fairness, timing or
  eventual painting is asserted.

## Remount and scope

[`AppView.svelte`](../src/AppView.svelte) keys the prompt by explicit path or
`"initial"`; workspace info, modules, analytics and query by workspace path;
target detail by label and snapshot fetch time; package by pattern; saved
invocation by selected ID; console by execution workspace and ID. Page/branch
changes can also destroy children without a key change. Within invocation
detail the comparison panel is keyed by workspace and shown ID, and the
timeline by profile object. `TargetActions` keys its disclosures by actions
payload. These boundaries determine which drafts, highlights, scroll positions,
subscriptions and timers belong to an old instance. They are **not** a general
TLC proof of Svelte remount or cleanup semantics.

Tree construction, query parsing/serialization/validation, search scoring,
comparison diffs, ANSI decoding, chart aggregation, timeline geometry and
formatting map inputs to outputs. Their results can influence transitions;
their correctness belongs to data/algorithm tests rather than an invented FSM.
